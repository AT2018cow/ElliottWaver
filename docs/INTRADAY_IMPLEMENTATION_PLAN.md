# 小时线与分钟线实施方案

供 DeepSeek 开发、Codex 独立验收。基线为 `v0.6.0`（`ca1dc3b`）。目标是在现有 `data fetch → analyze / brief → history / replay / settle` 流程中，用交易所会话内已完成的行情数浪，并在终端显示可以复核的判断条件。

交付范围为沪深个股、沪深主要指数、美股个股和 ETF，覆盖 `1m`、`5m`、`15m`、`30m`、`60m`，`1h` 归一为 `60m`。美股以常规交易时段为基准。原生美股指数在 IN-07 单独验收。生产验收以行情、艾略特硬规则和条件事件的正确性为准。盘中事件概率在有独立校准证据后另行评估。

## 基线与任务依赖

## IN-00　修正盘中简报的周线事件

- `outlook.py` 按主周期显式分派。`1d` 使用 5 个交易日，`1w` 使用 2 个完整交易周。IN-04 合入前，盘中 `Brief.outlook` 为空，`Brief.issues` 提示「此周期暂未提供短期观察」。保留已有候选、硬规则、价位和终端数据状态。
- 用 `demo --symbol 600519.SH --timeframe 1h` 和 `demo --symbol AAPL --timeframe 5m` 生成两份合成快照，再用 `brief --offline --snapshot ID --timeframe 对应周期 --format json` 分别验证终端和 `brief.json`。确认盘中简报显示专门诊断，周线事件只出现在对应的周线简报中。旧盘中报告照常按 manifest 读取。旧 `2W` 事件用于盘中结算时，返回「旧观察窗与主周期不匹配」诊断；原档案保留供历史查询。

## IN-01　行情适配、交易会话和聚合

沿用 `data/base.py` 的 `DataProvider.fetch`、`data/router.py` 的代码路由和 `data/workflow.py` 的入口。供应商归集代码放在 `data/`，引擎接收标准化的 `MarketDataBundle`。在 `DataConfig` 加 `cn_equity_intraday_feed`（默认 `sina`，可显式选 `tushare-cn-equity`）和 `cn_index_intraday_feed`（默认空，可显式选 `tushare-cn-index`）。选择结果写入 `Provenance.feed` 及缓存身份，供应商 Token 从本地环境或 `.env` 读取。美股个股使用现有 `--feed sip|iex`。日线和周线路由沿用各自的配置。

- **沪深个股**。保留新浪原生分钟与小时入口。另接能按日期时间分页的历史分钟源，优先试采 Tushare 股票分钟，按日期片段处理行数上限，核对 OHLC、时间标签、来源更新时刻和因子。近期源与历史源都要能独立说明覆盖范围。东方财富的公开 1 分钟接口近期覆盖有限，文档还提示旧交易日开盘价可能为零；用它作备用时，先用真实样本确认 OHLC 完整。 [Tushare 分钟取数](https://tushare.pro/document/2?doc_id=234) · [AKShare 分时接口](https://akshare.akfamily.xyz/data/stock/stock_quote.html)
- **沪深指数**。以 `000001.SH`、`000300.SH`、`399001.SZ` 验证指数身份与 OHLC。历史端接 `idx_mins`，供应商文档列明单次最多 8000 行，按时间回补并单独核验账号权限。盘中更新以同一只指数在交易时段的连续取数证据验收。只有历史证据时，矩阵显示「历史盘中行情可用」，发布范围注明更新能力。需要其他盘中源时沿用同一数据契约，独立配置 feed 后再验收。指数使用无复权价格，量价证据的可用性由 `volume_comparable` 表示。 [Tushare 指数分钟接口](https://tushare.pro/document/2?doc_id=419)
- **美股个股和 ETF**。继续用 Alpaca 核验资产 ID，按时间片段读取 `raw` 和 `all` 的全部分页。分开记录 SIP 与 IEX 的实际行情和可用时间。用已确认的股票类别与代码映射核对改名、类别股和 ETF；请求无权限时显示该 feed 的失败。 [Alpaca 历史行情接口](https://docs.alpaca.markets/us/reference/stockbars)

**时间和聚合契约**。沿用 `Bar` 的 `start_at`、`end_at`、`available_at`、`observed_at`。区间采用左闭右开，内部以 UTC 存储，终端按市场时区展示。适配器须把供应商时间标签解析成区间，分别记录行情何时按合约可用、实际何时取得。对历史回补按可用时刻截断属于冻结回放；有当时获取记录的行情才用作同期发行证据。

1. 在 `data/periods.py` 扩展会话校验与聚合，`data/quality.py` 负责缺口分类。沪深按上午、下午分别切分，美股从 RTH 开盘切分，在排定收盘处截断最后一个窗口。每个窗口需覆盖该时段预期的有价观测，输出 `O=首开，H=最高，L=最低，C=尾收`，数量仅在单位和来源一致时相加。聚合可用时刻取窗口结束、子项最晚可用时刻、供应商完成该窗口的时刻三者中的最晚值。
2. 有完整可信的 `1m` 时从它派生粗周期。可从可信 `5m` 派生其整数倍周期，也可使用覆盖更长的供应商原生小时线。快照记录实际来源粒度和聚合规则；同一序列的不同口径分别保存并验收。沪深原始价按统一基准复权后聚合；美股保留供应商的原始与复权序列。两组子项须逐区间配对，标的或边界错配时报告来源错误。
3. 静态无行情时隙由带版本的源规则确定。新浪沪深股票 1 分钟沿用已验收的稀疏集合竞价处理，保留收盘成交 bar。供应商间分别核对这段时隙和指数计算频率。单位缺失按不可比处理。停牌、已知无成交需要证据；未知缺口影响所需窗口时给出数据不足。一个窗口全部无价时记录空时隙，避免补造一根平价 K 线。

## IN-02　历史覆盖与增量缓存

在 `data/workflow.py` 根据周期、可用上限和请求区间建立盘中获取计划，替代个股两个适配器共同使用的 126 自然日截断。指标预热量和候选搜索长度使用 `AnalysisConfig` 的现有字段。源缓存和分析窗口分别配置，分析只读取有效窗口加预热。支持 `--start` 请求回补和 `--refresh` 复查尾段。有限历史源返回实得范围及原因。 [当前获取工作流](../src/elliottwaver/data/workflow.py#L17)

- 用现有 `SnapshotStore`、SQLite 和 Parquet。将可复用的标准源行情按交易日或连续小段索引。缓存主键包含资产 ID、feed、源周期、交易会话口径、复权口径、解析版本及日历版本。派生快照再包含聚合规则、父块 ID、请求决策截止与可用的日线背景。同一最终盘中 bar 但不同日线背景的请求分开查找；同一精确截止重跑直接命中已保存结果。
- 锁住同源同区间的更新，先校验再原子发布索引。重试同一页时去重，冲突的行情或因子生成新修订。历史片段按显式时间范围续跑；权限、空响应和中途失败保留已校验的片段及缺口，终端报告实际覆盖。未经证实的历史修订仍按冻结回放处理。
- `data inspect` 和盘中简报至少给出请求范围、实得首尾 K 线时刻、分析窗口、未知缺口数、实际 feed、价格口径、最后 K 线的结束和可用时刻。新增可选契约字段仅用于相应的新数据或报告；保留老版快照与 manifest 原有校验方式，读旧快照时按已存字段展示。

**验证**。使用记录调用次数的假供应商覆盖首次下载、重跑、尾段增量、复权修订、多个周期共享底层数据及并发失败重试。精确截止热命中零行情请求；真正使用同一已校验源块的周期切换零重复下载。不同 feed 和不同修订各自回放。

## IN-03　起浪时间和多周期证据

- 在 `schemas/market.py` 的请求和 `schemas/brief.py` 的锚点／范围中增加可选时间戳。CLI 的 `--anchor YYYY-MM-DD` 保留原日期语义。盘中额外接受带时区的 `--anchor YYYY-MM-DDTHH:MM:SS+HH:MM`，精确匹配 K 线 `start_at`。指定时刻对应的 bar 必须已可用，匹配失败给明确原因。`--as-of` 仍作为决策截止，`--start` 与 `--end` 继续接受交易日期。
- 从 `engine/span_selector.py`、`engine/matcher.py` 到 `service.py` 传递精确锚点；背景拐点映射到实际盘中极值，按 bar 时刻排序、去重和比较。换窗复核用两个不同的实际时间范围。日线和周线使用原有按日比较路径。预热不足有专门提示；搜索受预算限制时按已有状态反馈。
- 运行显式主周期时，按固定配对生成背景。`1m → 5m`，`5m → 60m`，`15m / 30m → 60m`，`60m → 1d`。同一底层行情按截止时刻聚合。小时与原生日线背景可以各自分析；只有价格口径和对应区间可核验时才给结构关联。日线背景只用决策时可用的原生完整日线。
- 在 `service.py` 增加 `hierarchical_v1` 的盘中入口，并在 `engine/timeframe_link.py` 扩展盘中腿区间映射。复用 `engine/rules.py`、`engine/hierarchical.py` 和现有子浪校验。仅当两个结果均为 `OK` 时比较方向。父子认证另核对同一资产、行情口径、时间包含、端点和请求的验证深度。缺细周期、端点对不上或证据尚未确认时，按已有未验证状态显示。深度 0 仅给端点证据，深度 1、2 分别要求对应认证层数。对同一输入复用指标、拐点，并让主选、背景和换窗使用可统计的搜索预算。

## IN-04　终端简报与固定观察期

在 `outlook.py`、`schemas/outlook.py` 与 `schemas/brief.py` 增加明确的盘中观察类型。盘中使用 `BriefOutlook.version = "1.1"`、`horizon_unit = "BARS"` 和 `horizon = 5`。每个 `OutlookPeriod` 内的 `start_at`、`end_at`、`end_session` 唯一描述一个主周期时隙，`sessions` 为单一交易日；允许五个时隙同一天。日周继续读取和写入原版契约。

1. 实时简报在最终形成判断时冻结 `issued_at`，它可以晚于读取行情的决策截止 `as_of`。普通冻结回放以 `as_of` 模拟发行。复跑一份实际发行的历史简报时，沿用记录中的发行时刻与观察窗。按发行时刻和当时的日历版本，从 `intraday_windows()` 取接下来五个 `start_at >= issued_at` 的已排定主周期窗口。周末、休市和午休自然跨过。发行前已知计划无价的时隙跳过，缩短会话的末段作为一个完整排定窗。首屏分别显示观察起止和最后一根已完成 K 线的截止时刻。
2. 从 `engine/projector.py` 取得当前浪、推进条件、当前证据、阶段退出和硬失效。沿用 `OutlookCase` 的主备身份和 `target_mode`。目标前置条件与比较符按原规则传递。历史不足、预算截断、日历不足或目标缺直接证据时，用明确的不可用或待确认状态。
3. 盘中 `Brief` 记录 `last_bar_end_at`、`last_bar_id`，沿用 `as_of`、`market_asof`，另外从快照显示最后一根的可用时刻。终端首屏先显示市场当地时间、周期及数据状态，再展示主备浪型、观察期限、触发条件和失效点。JSON 保存原精度，文字在简化目标范围时使用「约」，触发条件保留比较精度。用 `--format json` 保留终端文字并仅保存 JSON 文件。
4. `brief --timeframe auto` 线上沿用日／周自动选择。明确给出盘中快照时采用该快照的主周期。指定 `--timeframe 1h` 与 `60m` 走相同路径。跨周期派生只对同一资产、同一来源口径且具备完整底层数据的快照开放，支持从细周期到可整分的粗周期。

**手算例**。冻结沪深会话为 09:30–11:30、13:00–15:00。发行时刻为 11:27，`5m` 跳过已经开始的 11:25–11:30。五根从 13:00、13:05、13:10、13:15、13:20 开始，到期为 13:25。美股提前收盘日按 09:30–13:00 切 `60m`，12:30–13:00 是当天最后一根。两例都要测试发行前已开始、恰好开始和结束尚不可用的边界。

## IN-05　历史、事件结算和评估

| 改动处 | 实现契约 |
| --- | --- |
| `history.py`、`cli/main.py`、`brief.py` | SQLite 增量增加盘中最后一根的时刻及查询索引。盘中上一份报告按同一资产、周期、来源和相容的调整口径，选择更早的最后 bar 时刻，并要求其决策截止更早。实时报告还要满足当时已登记。重复生成同一根 bar 的历史对照时沿用此前合格记录。同日增量、重数和行情修订用源 bar 时间识别。旧档缺时刻时从校验后的主周期报告和已保存快照补录；缺证据的旧行仍可按日期查询。历史 CLI 支持可选 `--timeframe`，盘中行显示市场当地时刻。 |
| `evaluation/events.py`、`evaluation/outcomes.py` | 每个主周期注册 `ADVANCE_FIRST_{TF}_5B_V1` 和 `OUTLOOK_TARGET_FIRST_{TF}_5B_V1`，`TF` 为 `1M / 5M / 15M / 30M / 60M`。继承日周推进、目标、失效和阶段退出的状态语义。观察条目按区间起止配对并按时间排序。复用条件比较和事件求值；观察窗键从日期扩展为精确时段，日期字段保留作展示。 |
| `settlement.py`、`evaluation/decisions.py`、`evaluation/replay.py` | 正式简报、网格评估和结算共享同一个盘中观察窗解析器。核验报告、日历、资产、周期、feed 与价格依据。观察到的是在截止前完整可用的 K 线，结果附原始触发 bar ID、区间、价格口径和证据；复权换算使用发行坐标。结算继续按 `brief_digest + event_id + scope` 去重并保存修订。 |

按 **最早可核对的观察** 决定结果。一根 K 线同时触及可观察目标与停止，保留 `AMBIGUOUS_SAME_BAR` 和双方证据。对于 `AFTER_ADVANCE` 目标，推进与目标同根也标记次序不明，单独推进后的下一根开始观察目标。若前面有未知缺口，后续触发可能改变先达结论，该事件先归为 `INCOMPLETE_DATA`。快照覆盖尚未达到需要的可用时刻时为 `RIGHT_CENSORED`。排程冲突和复权不可比使用现有的 `SETTLEMENT_CALENDAR_MISMATCH` 与 `PRICE_BASIS_UNVERIFIED`。发行时已规划、后经可信来源确认的空时隙保留排定的到期时刻，观测结果记为无触价。同日多个事件按区间匹配，盘中事件清单只使用本周期的 ID。

**手算例**。推进条件 `HIGH >= 105`，目标区 `[110, 112]`，硬失效 `LOW < 98`。对于等待推进的目标，第一根最高 108、最低 99，第二根最高 111、最低 98，应在第二根标记 `TARGET_FIRST`。若第二根最低改为 97，应标记 `AMBIGUOUS_SAME_BAR`；若首根最高改为 111 且最低仍为 99，也因推进与目标同根标记次序不明。用同一组原始 bar 分别检验结算和评估。

离线评估区分分析特征与结果。对每条盘中决策保存精确截止、观察窗、触发时刻、数据来源和可用时刻，Parquet 保留这些字段。支持按固定间隔选主周期 bar 作为决策点。跨留出边界的事件按精确到期时刻裁剪。支持矩阵展示盘中可结算事件及未校准状态；日周模型的支持范围按原契约验证。

## IN-06　CLI 验收、样本和性能

以下是实现完成后的使用样例。先为目标市场选用已配置且有权限的数据源；报告路径及快照 ID 从前一步输出读取。

```bash
.venv/bin/elliottwaver data fetch 600519.SH --timeframe 1h
.venv/bin/elliottwaver analyze 600519.SH --timeframe 1h --format json
.venv/bin/elliottwaver brief 000300.SH --timeframe 15m --config config.yaml --format json
.venv/bin/elliottwaver brief AAPL --timeframe 5m --feed sip --format json
.venv/bin/elliottwaver brief AAPL --offline --snapshot "$SNAPSHOT_ID" --format json
.venv/bin/elliottwaver history AAPL --timeframe 5m --mode frozen --json
.venv/bin/elliottwaver replay "$SNAPSHOT_ID" --step 5 --output reports/intraday-replay.jsonl
.venv/bin/elliottwaver settle "$BRIEF_DIR" --snapshot "$OUTCOME_SNAPSHOT_ID" --json
.venv/bin/elliottwaver watchlist "$WATCHLIST" --timeframe 5m --workers 2 --json
```

### 自动化回归与独立验收
