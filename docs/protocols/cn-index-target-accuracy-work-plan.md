# 指数 20 日目标先达准确度改进计划

这份计划供 DeepSeek 实施。范围固定为 `TARGET_FIRST_20D_V1`、现有 7 个沪深京指数、`sina-index` 无复权日线和每周最后一个交易日的决策网格。交付一组可复现的开发期对照实验、一份候选失效条件审计，以及是否值得进入下一轮前向验证的结论。日用版沿用当前摘要和规则复核，正式概率继续由批准模型注册表控制。[冻结候选与前向验收](cn-index-target-forward.md)

## 现有证据与复现输入

- 2026 留出中，可判定的 1,590 个事件有 614 个先达目标。修正通用训练入口后，模型的 Brier 为 0.1863，价格基线为 0.1854，支持档覆盖率为 0%。改进重点是校准和相对价格基线的增益。[留出重算](../reviews/2026-11-20-cn-index-probability-recheck.md#2026-年留出重算)
- 另有 1,548 个事件未定义。其中 1,534 个缺少 `INVALIDATION`，14 个有失效条件但缺目标区。缺失效的候选中，716 个为 `COMPLETE`，其余分散在进行中阶段。三个数字分别从事件状态、`missing_invalidation` 和 `stage` 对账。
- 输入使用 `docs/protocols/cn-probability-release-2026.json` 中七个指数的原快照 ID，以及本地 `reports/cn-probability-release-2026/evaluation/` 的已校验评估。先核对清单、源码指纹、配置与数据文件哈希。现有数据范围已覆盖下列开发折。

## E1　滚动校准

在 `src/eliotbot/evaluation/calibration.py` 增加纯函数，接收已冻结的基础预测对数几率及此前可见的二元结果，只估计一个截距 `delta`。基础模型权重及静态校准参数在每个验证折开始前冻结。预测公式为 `p = sigmoid(z + delta)`，其中 `z` 是同一基础模型加静态校准后的正类对数几率。拟合最小化二元交叉熵的均值加 `0.1 * delta**2 / 2`，在 `[-2, 2]` 内可用二分求解。

首轮只测试一组预先约定的参数。每个决策取最近 12 个已有可用结果的不同决策日，每个日期保留其全部标的和候选。至少 8 个日期、100 条结果且正负各不少于 10 条时估计 `delta`。样本不足用 `delta = 0` 并记录原因。这些是本轮滚动校准的实验参数，正式发布门槛沿用原协议。

在研究回放里显式添加 `label_available_at`。采用保守口径，事件须到其预定到期会话，且该日 K 线已经可用。滚动更新只看 `label_available_at <= decision.as_of` 的明确结果。早触价也等到预定到期日，到期 K 线无法验证时，该行不参与滚动更新。开发期使用固定快照内到期 bar 的 `usable_at` 作可用时间，按冻结回放口径记录。每折可用已到期的校准段数据初始化；其基础分来自仅在该折训练段拟合的模型。该段分数按校准输入记录。

实现入口复用 `scripts/prepare_index_target.py` 的三组切分、`scripts/train_forecasts.py` 的拟合与 `forecast_evidence()`。逐决策日期从早到晚计算。每个预测至少保留决策时间、`delta`、样本行数、唯一日期数、最后一条标签可用时间和回退原因。实验结果与注册表独立，滚动状态先在研究回放实现。

**验收**

- 人工构造一条已先触价、尚未到期的事件。到期 bar 可用前它不影响 `delta`，可用时刻之后才进入窗口。用一条缺到期 bar 和一条同根双触及测试排除路径。
- 改写任意决策之后的事件标签，之前的概率、`delta` 和滚动窗口身份逐项相同。同一日期的候选全部使用同一版本的校准状态。
- 样本不足时输出与静态概率相同。给定相同输入和样本顺序，参数、预测及报告没有随机漂移。使用已有分块重抽样对比分数，保留日期内候选和指数的相关性。

## E2　接入目标区距离

在 `src/eliotbot/evaluation/features.py` 增加可选目标区特征。使用与 `first_touch()` 相同的首个目标区 `scenario.target_zones[0]`，在决策时的价格坐标计算。设区间为 `[L, H]`、决策收盘为 `C`。

| 字段 | 数值 |
| --- | --- |
| `target_distance_atr` | `max(L - C, C - H, 0) / ATR` |
| `inside_target_zone` | `L <= C <= H` 为 1，其余为 0 |
| `missing_target_geometry` | 缺目标、区间非法或 ATR 不可用时为 1，前两列置 0 |

已入区和已越过区间都只是决策特征。未来事件仍从下一交易会话按 `src/eliotbot/evaluation/outcomes.py` 的原规则判定。复用一份特征计算供 `evaluation/decisions.py` 和 `forecast.py`，避免研究与摘要口径漂移。新列进入目标先达模型时，也加到相同事件的完整价格基线。保留原确认距离、失效距离与现有动量对照。

通过协议字段 `feature_version` 显式选择新列。现有协议缺省为 `2`，列顺序与模型行为保留。新目标几何使用 `3`，同步校验评估清单、列顺序和候选哈希。用相同快照重放 2023–2025 的开发数据。按标的、周期、决策日期、快照 ID、候选 ID 和事件 ID 对齐 V2、V3，核对候选集合、标签、预定到期日和分段计数。

**验收**

- 目标区 `[100, 104]`、ATR 为 2。收盘 96、102 和 108 时，`(距离, 区间内)` 分别为 `(2, 0)`、`(0, 1)`、`(2, 0)`。补区间边界、多个目标区、无目标、无效 ATR 及涨跌镜像。
- 对同一固定快照，回放和摘要使用同一时点及首目标区，特征一致。旧 V2 评估清单和冻结候选仍可读取。版本混配或 V3 新列丢失时评分报错。
- 记录价格基线的列清单。两边使用同样的目标几何、标签与日期。V3 提升需对比含目标几何的价格基线。

## E3　核对候选为何缺失效边界

从历史事件明细导出 `stage × pattern × 缺失原因` 的计数和占比，复现 1,548／1,534／14 三个数。在 `src/eliotbot/engine/projector.py` 顺着规则分支逐类核查。优先抽查 `COMPLETE`、`B_DEVELOPING`、`C_DEVELOPING`、`W5_DEVELOPING`；另保留有失效缺目标的案例。每个代表例记录标的、决策日期、快照 ID、候选 ID、条件类型、规则依据和图。

把只可给阶段退出线的结构、确有硬规则但实现可能漏发的结构、数据证据不足的结构各自记录。无合法失效边界时继续 `UNDEFINED_EVENT`。发现漏发时先给冻结行情反例、涨跌镜像和独立预期。引擎规则修订后单列新的事件覆盖率，保持 E1、E2 四组对照的标签口径一致。

**验收**

- 从明细能复算每一类计数，各类分母有说明。`STAGE_EXIT` 仍用于阶段结束。
- 同期分别报告「具备目标与失效条件的候选占比」和「在支持档内可发布概率的占比」。

## 对照实验与收口

使用 `scripts/prepare_index_target.py` 的现有三组时间折。所有折的训练从 2023-01-01 开始，后两段从上一段结束的次日开始。逐段剔除预定到期日越界的事件。2026 年留出已有结果，供诊断和对账使用，本轮选择只依赖 2023–2025。

| 折 | 训练末日 | 校准末日 | 开发验证末日 |
| --- | --- | --- | --- |
| 1 | 2023-12-31 | 2024-06-30 | 2024-12-31 |
| 2 | 2024-06-30 | 2024-12-31 | 2025-06-30 |
| 3 | 2024-12-31 | 2025-06-30 | 2025-12-31 |

| 组 | 特征 | 校准 |
| --- | --- | --- |
| A | V2 | 固定带截距校准，对照 |
| B | V2 | 固定校准加滚动截距 |
| C | V3，加入目标几何 | 固定带截距校准 |
| D | V3，加入目标几何 | 固定校准加滚动截距 |

四组同折同样本对账。频率、动量、价格基线各保留。报告模型加滚动校准后对固定基线的结果，也报告给基线应用同样滚动校准后的直接对照，以识别收益来自校准还是波浪特征。逐折及合并报告 Brier、log loss、分档预测与发生率、95% 配对区间、可结算覆盖率、支持档覆盖率和回退频率。同组内按事件行等权合并折指标。候选入选需两项合并损失均不高于 A，且至少一项低于 A。入选方案按 log loss 选唯一候选，平局优先改动较少的方案。若未发现改善，结束本轮试验并保留 A，归档负结果。

进入发布验证的候选冻结参数、特征版本、滚动规则、基线、日期网格、快照与源码指纹。使用冻结后独立到期的新增样本做一次评分。此前规划的 12–16 个时间块用来估算样本量，正式门槛用原协议。Brier 和 log loss 相对三条基线的配对 95% 改善区间下界大于零。留出至少 50 条、10 个日期、5 个标的。每个拟发布档至少 50 条、10 个日期、2 个占用时间块，校准差的 95% 区间在 ±0.10 内，整体支持档覆盖率至少 50%。新样本不足时，工单交付状态为「研究完成，待新留出」。

## 交付给验收者

1. 提交 E1、E2 的代码与因果回归，给出 E3 的审计明细和建议。保持已冻结候选和旧评估产物可读。
2. 在 `reports/index-target-accuracy/` 保存演练协议、四组逐决策概率、校准状态、指标、选型理由和文件校验清单。对照入口可设为 `scripts/compare_index_target.py`，接收 `--v2-evaluation`、`--v3-evaluation` 和 `--output-dir`，统一读取已验明细并输出上述产物。记录从仓库根目录执行的完整命令。
3. 在 `docs/reviews/` 保存验收记录并加入索引，注明实验范围、实际样本量、是否优于对照、是否具备前向证据。通过现有测试、Ruff 与离线个股／指数摘要烟测。正式发布由新留出验收后单独处理。
