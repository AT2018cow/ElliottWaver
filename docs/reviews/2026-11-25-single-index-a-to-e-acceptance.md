# 单指数中短线 CLI 的 A 至 E 批整体验收

**暂缓整体签收。** 在正常的冻结行情上，单指数简报、主备浪型、短线与波段点位以及后续核销均能复算。另有四个可重复的反例。前两项会把缺乏当时行情支持的触发或达标记入历史，第三项会改变历史回放所使用的日线预案，第四项影响硬失效发生率的统计上界。

以上为首次验收结论。四项问题的修复和结果见文末的[修复复验](#修复复验)。

验收基线为 2026-11-25 的提交 `Implement and harden intraday index forecast calibration`。范围采用实施方案第 1 节的本地人工操作约定。各项核查在本地 Python 3.12.3 完成。行情取自既有冻结快照，延迟、修订及同根先后使用受控输入。[当前交付范围](../SINGLE_INDEX_TRADING_IMPLEMENTATION_PLAN.md#当前验收范围)

## 复现的缺陷及复验条件

### AE-01 · P1 · LIVE 日线预案把迟到行情记为准时触发

用 SPX 测试预案设收盘门槛 100。首个会话收 98，次个会话收 101。后者名义收盘与激活截止同为 2025-02-03 21:00 UTC，原始和分析 K 线实际均于 21:10 才收到。以 21:10 为观察截止，LIVE 状态为 `TRIGGERED`，激活时刻和转换的可观察时刻均记为 21:00。日线观察只取 `usable_at`，盘中路径已区分名义可用与实际接收。日后查看历史会误以为当时已具备操作条件。[日线观察](../../src/elliottwaver/index_guidance.py#L568) · [盘中可见时间](../../src/elliottwaver/index_intraday.py#L39)

**复验条件**　此例在 LIVE 下应到期且无触发，转换的可观察时刻应覆盖完整证据的实际接收。补测早一根迟到、此前运行已保存及时接收证据，以及恰好在截止收到的情况。冻结回放继续按已声明的名义时刻复算。

### AE-02 · P1 · 修订后的行情可继承缺乏依据的达标结果

原两根后续日线的最低、最高、收盘分别为 (97, 103, 101) 和 (97, 109, 99)。预案第一天收盘越过 100，第二天触及 108。保存达标观察后，把第一根修订为 (97, 99, 98)，第二根保持原样。以修订快照结算，带有旧观察的报告得到 `TARGET_REACHED / OK`，仍引用旧激活 K 线。同一修订快照从原始发行重新算得 `EXPIRED`。两行归属同一快照。核销核验了最后观察的 bar 身份，未核验中间的激活证据。[快照覆盖检查](../../src/elliottwaver/evaluation/index_plans.py#L48) · [沿用已有观察](../../src/elliottwaver/evaluation/index_plans.py#L73)

**复验条件**　保留当时原始观察及其来源。用修订快照重算时，应明确标记修订、另存重算结果或拒绝把旧观察归给新快照。原始发行和后续已达标报告两种入口均须验证。

### AE-03 · P2 · 同一日线的回放先后会改变次日承接的预案

在空缓存中，对同一份科创50快照先运行 2024-08-15 07:45 UTC 的 `brief`，再运行 07:30 UTC 的 `brief`，两次均使用上述上行案例开关。两份短线预案 ID 分别为 `0878dda3c695b5f69ba46a15` 和 `02e5b33a1c6344d74bd22608`。次日 02:30 UTC，两份日线在模拟时间上均已可见。调用 15m 的父预案解析器时，选中最后写盘的 07:30 报告。次日日线的 `HistoryStore.previous` 也选中 07:30。两份发行的源证据都能读取，错误出在历史排序使用了本机执行回放的时间。[盘中父预案查询](../../src/elliottwaver/cli/index_context.py#L60) · [历史查询排序](../../src/elliottwaver/history.py#L528) · [日线前序选择](../../src/elliottwaver/history.py#L549)

**复验条件**　将同一组已发行的两份回放报告正序、逆序登记到两个空目录。07:40 查询应选 07:30，次日查询均应选 07:45，且两档的预案 ID、版本和来源一致。LIVE 查询另以真实发行回执判断当时能否读到。

### AE-04 · P2 · 同根阶段退出会被统计成可能的硬失效

设硬失效为最低价低于 96、阶段退出为低于 98、目标为 108。首日以 101 激活，次日最高 109、最低 97。目标和阶段退出先后未知，但硬失效价从未触及。单预案的第 2 会话统计中，目标区间为 0%–100%，硬失效上界也为 100%。状态机将两种退出合并成相同原因，统计端将这类歧义同时列入两种事件的上界。[状态转换](../../src/elliottwaver/index_guidance.py#L595) · [歧义分类](../../src/elliottwaver/evaluation/index_plans.py#L166)

**复验条件**　该样本应保留目标区间 0%–100%，硬失效区间应为 0%–0%。增加最低价确实穿过 96 的对照，验证统计分别保留各类实际触及的条件。

AE-01、02、04 可分别用 `tests/test_index_plans.py` 的 `origin`、`projected`、`subsequent` 构造上述两根日线。AE-01 修改的是原始和分析 bar 的 `observed_at`。AE-02 先把 `observe_plan` 得到的观察和转换放回原 track，再以同一修订快照对该 track 与初始 track 分别调用 `settle_index_track`。AE-04 在预案中增加上述 `STAGE_EXIT`，查看 `summarize_index_plans` 的 `from_activation.by_session["2"].invalidation_ambiguity_range`。AE-03 使用真实冻结日线、独立缓存及实际 CLI 写入的历史。

## 修复复验

| 编号 | 修复及回归证据 |
| --- | --- |
| AE-01 | LIVE 同时核对原始和分析 K 线的实际接收时刻，并按连续会话的最晚时间判断是否赶上截止。刚好在截止收到可触发，晚 10 秒则到期。首根晚于第二根收到时也不会回填成准时触发。已有观察保留此前记录的时间，冻结回放沿用名义可用时间。 |
| AE-02 | 核销核对已有的激活 K 线及最后观测 K 线。新观察另记录完整观测前缀的证据摘要。改写激活日，或在激活和达标之间插入硬失效的修订，均拒绝把旧达标结果归给新快照。从初始报告重算仍可取得该快照对应的结果。 |
| AE-03 | 冻结回放按决策截止排序，并在截取候选前排除当时不可见的报告。将同一组报告反向登记后，较早截止仍只可见 07:30，次日两条承接路径均选 07:45。科创50用正式 CLI 倒序补跑也验证了次日盘中父预案选择。 |
| AE-04 | 同根碰目标与阶段退出时，目标区间仍为 0%–100%，硬失效区间为 0%–0%。确实触及硬失效位的对照中，硬失效上界仍为 100%。旧的通用歧义原因在核销能核验退出 K 线时按该 K 线判定。 |

正式 CLI 复验中，SPX 合成样本的原快照保持“目标已达”。对同一预案的初次发行使用修订快照得到“到期未触发”，已达标报告则拒绝该修订快照。科创50真实冻结样本在 2024-08-15、16、19 三次运行间保留原预案 ID，两档均在第三次运行到期。隔离安装的 wheel 读回相同核销结果。
